# Temporary analysis — Leatherworker infusion trades

Status: implementation working document; delete before merge/release.

## Current Alchemical Leather

- `Infusions` already owns the serialized humanoid and BODY components and resolves normal potion contents into timed/stable/instant entries.
- Humanoid armor is slot-gated by `EffectSlotRules`; BODY accepts potion bundles.
- Dyeability discovery is intentionally broad and server-authoritative. That is unsuitable as the villager economy allowlist, so trading needs separate item tags.
- Potion color is already represented as `minecraft:dyed_color` on infused armor.

## Minecraft 26.2 trade model

- `VILLAGER_TRADE` and `TRADE_SET` are data-driven registries.
- Leatherworker level tags currently contain 2 candidates at IV and 2 at V; ordinary TradeSets select 2 offers.
- `VillagerTrade` supports an item template, an optional second cost, output loot-item modifiers, max uses, XP and reputation discount.
- A loot-item modifier can replace the result ItemStack and can attach `ADDITIONAL_TRADE_COST`; `VillagerTrade` removes that component and adds it to the first cost.
- The villager trade loot context explicitly permits the additional-cost component.
- Therefore we can append exactly one Expert and two Master registry trades through vanilla tags and keep the desired candidate probabilities without replacing vanilla TradeSets.

## Why a custom output loot function

Defining every armor/effect pair as its own `villager_trade` would dilute candidate probabilities because each pair becomes a separate TradeSet candidate. A single custom loot function per category can instead select one valid armor/potion pair internally while each category remains one villager-trade candidate.

The function should be data-driven through item/potion tags, with only policy invariants in Java. This gives mod/datapack extensibility while keeping Reorientation, tier caps and slot rules enforceable.

Selection should be two-stage: choose a valid armor item first, then a valid potion for that armor slot. Uniformly enumerating all item/potion pairs would accidentally make BODY armor much more common simply because its potion union is larger.

## Proposed default pools

Expert timed:
- LEGS: Swiftness I, Leaping I.
- FEET: Slow Falling I.

Master timed:
- HEAD: long Night Vision I, long Water Breathing I, long Invisibility I.
- CHEST: Strength II, Regeneration II, long Fire Resistance I; optional Scale Brews Growth II/Shrinking II.
- LEGS: Swiftness II, Leaping II.
- FEET: long Slow Falling I; optional Alex's Mobs Clinging I (`alexsmobs:clinging`).
- BODY: union of useful Master timed effects, including optional Scale Brews II and Alex's Mobs Clinging I. No Turtle Master.

Master persistent:
- HEAD: Night Vision I, Water Breathing I.
- CHEST: Fire Resistance I, Strength I, Regeneration I; optional Scale Brews Growth I/Shrinking I.
- LEGS: Swiftness I, Leaping I.
- FEET: Slow Falling I; optional Alex's Mobs Clinging I.
- BODY: union of the persistent-safe pools. No Invisibility/Turtle Master/instant/debuff/ominous reactive effects by default.

Clinging Reoriented does not own the Clinging potion; it adds `clinging_reoriented:reorientation` on top of Alex's Mobs Clinging. Reorientation is mechanically supported by existing Alchemical Leather rules but must be hard-rejected from villager trades.

## Risks

- Custom loot function registration must happen before data-driven villager trades decode.
- Item/potion tag references to optional mods must use `required:false`.
- The output selector must validate actual `EQUIPPABLE` slot, Alchemical dyeability, potion effect count, slot mapping and tier amplifier bounds before choosing.
- Dynamic datapack extensions could try to smuggle forbidden entries in; hard bans/caps need runtime checks.
- A trade function returning empty stack causes `VillagerTrade.getOffer()` to omit the offer, which is the desired degraded behavior when no candidates are valid.
- Tests must inspect actual profession TradeSets/tags, not only helper methods, or a resource-path typo could pass unit-style checks while the feature never appears in game.
