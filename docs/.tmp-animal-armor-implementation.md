## Native dyed-water cauldron

- [ ] Add `alchemical_leather:dyed_water_cauldron` with six internal fluid levels and ordinary-cauldron clone/drop semantics.
- [ ] Add a synchronized block entity storing the dyed-water RGB color.
- [ ] Add blockstate/assets/tags/loot so the block renders as a normal water cauldron at visual levels 1/2/3 while its liquid tint comes from the block entity.
- [ ] Register client block-color handling for the dyed-water block.
- [ ] Add a shared brightness-preserving RGB blend helper matching Minecraft/BedrockIfy dye semantics.
- [ ] Recognize dyes by `DataComponents.DYE` rather than concrete `DyeItem` classes.
- [ ] When BedrockIfy's cauldron feature is not positively active, dye on vanilla water converts levels 1/2/3 to native dyed-water levels 2/4/6 and consumes one dye only when color changes.
- [ ] Additional dye on native dyed water blends color without changing fluid amount; identical-result blends do not consume dye.
- [ ] Dyeing qualifying armor from native dyed water blends with existing `DYED_COLOR`, preserves infusion/other components, consumes one of six fluid units, and empties on the last unit.
- [ ] Glass bottle extraction consumes two dyed-water units and returns a normal water potion.
- [ ] Full dyed-water cauldron plus empty bucket returns a water bucket and empties the cauldron.
- [ ] Water potion/bucket refill removes the tint and converts quantity back to vanilla water using BedrockIfy-compatible 2↔1 volume rules.
- [x] Vanilla water washing already removes both infusion formats plus `DYED_COLOR` for qualifying dyeable armor and consumes one vanilla water level.
