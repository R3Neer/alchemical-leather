# Temporary architecture plan — Leatherworker infusion trades

Status: implementation working document; delete before merge/release.

## Design

1. Add `trade/InfusedArmorTradeFunction` implementing `LootItemFunction` with codec field `tier` (`expert`, `master_timed`, `master_persistent`). Register its MapCodec in `BuiltInRegistries.LOOT_FUNCTION_TYPE` during mod initialization before server-data registry decode is needed.
2. Add `trade/LeatherworkerTrades` as policy/data access layer:
   - item tag keys for Expert and Master armor pools;
   - potion tag keys by tier and equipment slot;
   - hard invariant validation;
   - candidate enumeration and weighted/equal random selection;
   - result construction and price premium calculation.
3. Keep trade-category cardinality stable by adding exactly three data-driven `villager_trade` entries:
   - Expert timed: base 10 emeralds, max uses 3.
   - Master timed: base 16 emeralds, max uses 2.
   - Master persistent: base 28 emeralds + 1 Dragon's Breath, max uses 1.
   Each starts with a harmless vanilla leather item template but the custom function replaces it with the selected validated result.
4. Append Expert entry to `#minecraft:leatherworker/level_4`; append both Master entries to `#minecraft:leatherworker/level_5`. Do not override vanilla TradeSets.
5. Add economic item tags:
   - Expert: leather leggings, leather boots.
   - Master: leather helmet/chestplate/leggings/boots, leather horse armor, wolf armor.
   Custom datapacks/mods can extend them, but runtime validation requires actual infusible dyeable armor and enforces tier slots.
6. Add potion tags by slot/tier. Optional `scalebrews:*` and `clinging_reoriented:*` entries use `required:false`.
7. Candidate validation:
   - Expert: slot LEGS/FEET, exactly one non-instant effect, amplifier 0, timed.
   - Master timed: HEAD/CHEST/LEGS/FEET/BODY, no instantaneous effect, amplifier <=1, humanoid single-effect mapping must match slot, BODY accepts the curated single-effect trade potion.
   - Persistent: same Master slots, exactly one non-instant effect, amplifier 0; convert to stable mode.
   - all tiers: reject Reorientation by effect ID; reject any level III+; reject invalid/missing dyeability or enchanted results.
8. Construct result:
   - create fresh stack of chosen tagged item;
   - set humanoid `Infusions.TYPE` or BODY `Infusions.ANIMAL_TYPE`;
   - set `DYED_COLOR` from chosen potion contents;
   - set `ADDITIONAL_TRADE_COST` to variant premium so first cost lands in target tier range.
9. Price policy: piece premium + effect premium, clamped to category target maximum. Dragon's Breath stays second cost and therefore cannot be removed by reputation discounts.
10. Tests use actual registry/tag lookups and trade `getOffer` paths where practical, plus deterministic validation helpers for all policy invariants.

## Compatibility boundaries

- No Java compile dependency on Scale Brews or Clinging Reoriented.
- Default optional potion tags are inert when mods are absent.
- `Reorientation` remains mechanically infusible where existing rules allow it but economically untradeable.
- No change to cauldron, effect ledger, BedrockIfy ownership or dyeability classifier.
