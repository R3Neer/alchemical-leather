# Temporary architecture plan — effectless potion cauldrons

Status: TM working document. Delete before merge.

## Proposed architecture

1. Add a small `PotionContents` predicate in the cauldron layer that answers only whether stored contents contain any effects. Do not weaken `Infusions.resolveAll` or `resolve`; those remain infusion validators.
2. Bottle insertion validates that `POTION_CONTENTS` exists, but no longer requires infusion resolution before storage. Existing water special-casing remains first-class.
3. Armor interaction branches by source contents:
   - effectless: dye-only transaction;
   - effectful: existing infusion transaction unchanged.
4. The dye-only transaction:
   - requires exact server-side Alchemical Leather dyeable armor classification;
   - copies the stack, updates only `DYED_COLOR`, preserves all infusion/enchantment and unrelated components;
   - consumes one own/BedrockIfy potion dose only after eligibility succeeds;
   - uses the same feedback/stat transaction boundary as infusion.
5. Keep own and BedrockIfy potion sources on the same armor branch so foreign ownership remains limited to fluid lifecycle and exact dose consumption.

## Review 1

The split belongs in `CauldronService`, not `Infusions`: zero effects are invalid as an infusion but valid as cauldron contents. Changing `resolveAll` to produce an empty `AnimalInfusion` would violate the data-model invariant and contaminate runtime effect code.

## Review 2

Stable. Preserve water behavior and effectful rejection semantics. Proceed to tests-first implementation.
