# Temporary analysis — effectless potion cauldrons

Status: TM working document. Delete before merge.

## Root cause

`CauldronService` currently validates a bottle with `Infusions.resolveAll(incoming, stack.getItem())` before it writes the potion into the cauldron. `resolveAll` intentionally returns `no_effect` for zero-effect potion contents because it answers the infusion question. That same function is therefore being misused as a storage validator.

The armor path has the same coupling: every potion-cauldron armor interaction immediately tries to resolve an infusion, so an effectless source cannot reach the already-existing `DYED_COLOR` application.

## Design implications

Storage and infusion eligibility are independent concerns:

- A potion cauldron can preserve valid potion contents even when those contents are not infusible.
- Dye color comes from `PotionContents.getColor()` and does not require an effect.
- Effectless contents therefore have a well-defined useful operation: color transfer only.

The safest discriminator is whether `PotionContents.getAllEffects()` is empty. This avoids changing `Infusions.resolveAll`, whose current `no_effect` result remains useful and correct for callers that truly require an infusion.

## Edge cases

- `incoming == null`: still invalid; ordinary potion items should carry `POTION_CONTENTS`, but malformed stacks must not create an invalid cauldron.
- water potion: preserve the existing vanilla water route on an ordinary cauldron.
- enchanted compatible armor: allow effectless dye-only use because no infusion is being created and ordinary dyeing is not mutually exclusive with enchantments.
- already infused armor: preserve infusion when effectless dye-only use changes its color, matching dyed-water behavior.
- BODY armor: same dye-only path; no empty `AnimalInfusion` is created because its invariant is non-empty.
- effectful unsupported/multi-effect potion on humanoid armor: unchanged rejection; do not silently downgrade an effectful potion to dye-only.
- no-op RGB: potion-cauldron armor use still consumes a liquid dose, like ordinary dye-bath use; the resource being consumed is the potion dose rather than a dye item.
- BedrockIfy imported effectless potion: shared armor logic can dye-only after reading the foreign snapshot, while bottle lifecycle remains delegated.
