# Temporary requirements — effectless potion cauldrons

Status: TM working document. Delete before merge.

## User-visible behavior

1. Non-water potion stacks with valid `PotionContents` must be pourable into an Alchemical Leather cauldron even when they contain no effects. This includes vanilla awkward, mundane and thick potions and equivalent modded/custom effectless potion contents.
2. Normal, splash and lingering bottle types all follow the same ordinary Use path and preserve their bottle type in the cauldron.
3. An effectless potion cauldron is a dye bath, not an infusion source. Using compatible dyeable armor on it consumes one dose and applies the potion cauldron's current visible RGB through `DYED_COLOR`.
4. Dye-only application preserves existing Alchemical Leather infusion components, enchantments, trims, durability, names and unrelated components. It must not create or remove an infusion.
5. Effectless dye-only application follows the same armor eligibility boundary as other Alchemical Leather dyeing: genuinely compatible/dyeable armor only. Arbitrary non-dyeable armor is not made visually dyeable by attaching an unused component.
6. Water potions keep Minecraft/Alchemical Leather's existing water-cauldron and dyed-water semantics rather than becoming potion cauldrons.
7. Effectful potion infusion rules remain unchanged: enchantment exclusion, humanoid slot mapping, BODY bundle behavior, multi-effect restrictions and unsupported-effect errors still apply when effects exist.
8. Matching effectless refills use normal potion identity rules and preserve a custom cauldron tint.
9. Glass-bottle extraction must round-trip effectless contents and original bottle type.

## Compatibility

- BedrockIfy continues to own ordinary bottle lifecycle for its own potion cauldron. If an imported BedrockIfy potion cauldron exposes valid effectless contents, Alchemical Leather's armor-specific action should treat it as dye-only under the same rules.
- No new compile-time optional-mod dependency.
